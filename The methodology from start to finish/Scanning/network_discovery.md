# Reference Note: Theoretical Network Discovery and Defensive Audit Mechanics

## 1. Fundamentals of Network Discovery: Layer 2 Mapping

Network mapping is the foundational step of any security audit. It begins at the Data Link Layer (Layer 2), where the primary objective is to identify active hardware within a local network segment. This process relies on the Address Resolution Protocol (ARP) to resolve IP addresses to physical MAC addresses. By performing an ARP sweep, an auditor can determine which systems are live and communicating before attempting to analyze specific ports or services.

### Core Discovery Tools

| Tool | Primary Mechanism and Auditing Goal |
| :--- | :--- |
| `arp-scan` | **ARP Scanning:** Sends ARP packets to every host in the local range (e.g., `target_subnet/24`). Identifies active hosts and their MAC addresses even if they are configured to ignore ICMP "ping" requests. |
| `netdiscover` | **ARP Sweeping:** Actively sends ARP requests or passively sniffs for ARP traffic to map the network. Used to identify the MAC-to-IP relationship for all live systems within a segment. |

Theoretical Mechanics of TCP Port ScanningOnce a host is identified, the auditor must determine which ports are open. This interaction is based on the TCP Three-Way Handshake (SYN, SYN-ACK, ACK). While a standard connection completes all three steps, security auditors often utilize "Stealth Scanning" to identify open doors without establishing a full connection.The Stealth Scan (SYN Scan) ProcessThe SYN Request: The auditor sends a SYN (Synchronize) packet to a specific port on the target system.The Response (SYN-ACK vs. RST):If the port is open, the target responds with a SYN-ACK (Synchronize-Acknowledge).If the port is closed, the target responds with a RST (Reset).The Final Reset (RST): In a stealth scan, the auditor does not send the final ACK to complete the handshake. Instead, a RST packet is sent to terminate the interaction immediately.Command ReferenceBashsudo nmap -sS -p- 192.168.1.100
